# Design-Partner Funnel

Пайплайн готовит аутрич дизайн-партнёрам HAIA по базе аккаунтов в Notion: находит у каждой компании свежий проверяемый повод, по правилу выбирает оффер, пишет 4 касания (email, LinkedIn, email, переадресация), прогоняет их через проверки кода и независимого рецензента и кладёт карточку в Notion на ревью.

**Пайплайн ничего не отправляет.** Отправка — вручную, после одобрения.

Все правила — в [`SPEC.md`](SPEC.md). Код их только исполняет: что брать, сколько заходов делать, какой оффер, кому писать первым и прошёл ли текст проверки, решает код. Модель получает фиксированные промпты и обязана вернуть JSON по схеме.

## Как это устроено

| Этап | Что делает | Кто решает |
|---|---|---|
| `select` | Аккаунты и контакты из Notion по фильтрам `config.yaml`; брак пропускается, тёплые интро — отдельно | Код |
| `research` | Заход 1: код собирает корпус (Google News, sitemap сайта, вакансии Greenhouse/Lever/Ashby, YouTube), модель извлекает поводы. Заход 2: углубление веб-поиском. Заход 3: рыночный повод | Код + модель |
| — проверка поводов | Цитата сверяется со страницей; уровни свежести hook / state / context / stale | Код |
| — план | Когорта, основной повод и оффер, зацепка, основания дня 3 | Код (`pipeline/rules.py`) |
| `people` | Снизу вверх: Findymail → веб ×2; кандидаты проверяются по источнику; новые люди пишутся в базу контактов | Код + модель + поставщик |
| `write` | 4 касания на каждого контакта с email | Модель |
| — проверки | Поздравления, длины, запрещённые фразы, HAIA в теле, числа без источника, правило дня 3, подписи | Код (`check_package`) |
| `review` | Независимый рецензент; при FAIL — одна переписка | Модель, отдельный вызов |
| `publish` | Карточка аккаунта в Notion + поля эксперимента на строках контактов | Код |

Статусы аккаунта: `selected → planned → people_ok → written → ready → published`. Холды: `on_hold` (нет повода после трёх заходов), `needs_people` (нет исполнителя после всех заходов поиска). Оба автоматически перепроверяются через 7 дней. Ещё есть `check_failed`, `review_failed`, `error`. Ошибка одного аккаунта не останавливает батч.

## Установка

1. Python 3.11+:
   ```bash
   pip install -r requirements.txt
   ```
2. **Claude Code CLI**, вход в аккаунт с подпиской (платный API не используется):
   ```bash
   npm install -g @anthropic-ai/claude-code
   claude            # один раз войти в аккаунт, затем выйти
   claude -p "ok"    # должен ответить без вопросов
   ```
   Пайплайн вызывает `claude -p --output-format json --model <алиас> [--allowedTools WebSearch,WebFetch]`. Проверено на Claude Code 2.1. Если флаги в вашей версии другие, поправьте `pipeline/llm.py::ClaudeCLI.build_cmd`.
3. Проверка без сети и без модели:
   ```bash
   python -m pytest -q
   python run.py eval
   ```

## Настройка

1. **Доступы — только переменные окружения**, не в репозитории:
   ```bash
   export NOTION_TOKEN=secret_...        # выдаёт администратор Notion: внутренняя интеграция с доступом к базе аккаунтов, базе контактов и странице карточек
   export FINDYMAIL_API_KEY=...          # необязательно, но для снизу вверх в компаниях 51+ почти обязательно
   export YOUTUBE_API_KEY=...            # необязательно
   ```
   Без Findymail люди ищутся только в вебе. Найденные без email записываются в базу со статусом «Нужно обогатить», и аккаунт ждёт на `needs_people`.
2. `cp config.example.yaml config.yaml` и заполните:
   - `accounts_data_source_id`, `contacts_data_source_id` — ID **data source** (не database). Откройте базу в браузере, скопируйте ID из адреса (32 символа), затем:
     ```bash
     curl -s https://api.notion.com/v1/databases/<ID> -H "Authorization: Bearer $NOTION_TOKEN" -H "Notion-Version: 2025-09-03" | python -c "import sys,json;print([d['id'] for d in json.load(sys.stdin)['data_sources']])"
     ```
   - `output_parent_page_id` — страница для карточек.
   - Названия полей обеих баз уже вписаны по реальной шапке базы контактов; сверьте, если базу меняли.
3. **В базе контактов вручную** (API не создаёт опции статуса):
   - добавьте опцию статуса **«Нужно обогатить»**;
   - создайте поля эксперимента и впишите их названия в `contacts.write`: тип оффера (select), тип повода (select), когорта (select), уверенность (select), карточка (url), день старта (number).
4. Необязательно: поля `Воронка — статус` (select) и `Воронка — карточка` (url) в базе аккаунтов → `funnel_status` / `funnel_page`.

## Запуск — по порядку

1. Проверка без сети: `python -m pytest -q && python run.py eval`.
2. **Замер** — 30 аккаунтов по сегментам, исследование и люди, без писем:
   ```bash
   python run.py measure
   ```
   Смотрите `runs/<время>/MEASURE.md`. Сегменты ниже порога (70% с поводом, 70% с людьми) дорабатываются до писем.
3. Пробный батч без записи в Notion:
   ```bash
   python run.py all --batch 5 --dry-run
   ```
   Результат в `runs/<время>/`: по каждому аккаунту `.json` и `.md` (заходы, поводы, план, люди, проверки, тексты), плюс `SUMMARY.md`.
4. Рабочие батчи и ручная выборка:
   ```bash
   python run.py all --batch 20
   python run.py sample --run runs/<время> --n 5
   ```
   Батч сам останавливается на стоп-условиях (SPEC §8); `--force` — только осознанно.
5. **Еженедельно** — перепроверка холдов (cron, например по понедельникам):
   ```bash
   0 7 * * 1  cd /path/to/design-partner-funnel && python run.py recheck
   ```

Конкретные аккаунты: `--ids "HitPay,Nomod"`. Этапы по отдельности: `select`, `research --run …`, `people --run …`, `write --run …`, `review --run …`, `publish --run …`.

Параллельность — `selection.parallel`. Лимиты подписки общие для всех вызовов: если упираетесь, уменьшите `parallel` и `batch_size`. Findymail списывает кредит только за найденный email; 286 аккаунтов × 2–3 человека ≈ 600–900 поисков.

## Правила качества (обязательно)

- **Ручная выборка в каждом батче:** ≥5 случайных аккаунтов. Брак в 2+ из 5 — батч останавливаем, причину превращаем в правило (SPEC §8).
- **Нет повода — нет письма.** Холды не дописываются вручную «из общих слов»: они уже прошли все заходы и перепроверяются автоматически.
- **Изменение правил** = правка `SPEC.md` + кода/промптов в одном коммите + `python run.py eval` (и `--live` для промптов) + решение Ильи. Правки не дописываются снизу документа — меняется нужный раздел и журнал решений.
- Эталоны в `golden/` — одобренные Ильёй тексты. Их не правят без его решения.

## Структура

```
SPEC.md               правила воронки (источник истины)
config.example.yaml   шаблон настроек без доступов
run.py                оркестратор этапов
pipeline/
  rules.py            выбор оффера, размер/уровни контактов, проверки текстов
  verify.py           проверка цитат по ссылкам
  collect.py          корпус кода: Google News, sitemap, вакансии, YouTube
  providers.py        Findymail: сотрудники, поиск и проверка email
  stages.py           этапы select / research / people / write / review / publish
  llm.py              вызов claude -p и валидация JSON
  notion.py           клиент Notion API
  render.py           карточка Notion и markdown-отчёт
  models.py           схемы данных
prompts/              промпты: извлечение, углубление, рынок, люди, письма, рецензент
golden/               эталонные аккаунты (HitPay, NextPay, Nomod, Dibsy)
evals/run_eval.py     регрессия на эталонах
tests/                тесты без сети
```
